# Отчёт: ремонт AI Screen Bridge (рой агентов + ручная доводка)

Дата: 2026-11-08. Затронутые файлы: `screen_agent.py`, новые модули `agent_window.py`,
`agent_progress.py`, `agent_speed.py`, тесты `test_agent_window.py`, `test_agent_progress.py`,
`test_agent_speed.py`.

## Что было не так (симптомы из лога 11:20–11:21)

1. **Окно программы перекрывало тест на скриншотах.** Модель писала «active tool window
   covering the answer options» и тыкала почти в центр области наугад. Дополнительно клики без
   проверки могли уходить в само окно программы — экран тогда не менялся вовсе.
2. **Цикл кликал одну и ту же точку шесть раз подряд.** Между шагами не было никакого состояния:
   ни истории кликов, ни сравнения кадров, ни счётчика повторов. На неподвижном экране модель с
   temperature=0.1 детерминированно возвращала ту же точку.
3. **Шаг занимал 5–8 секунд.** Замер на этой машине: локальная подготовка ~0,1 с (захват 72 мс +
   JPEG 17 мс), остальное — API. Но объём задаёт наша сторона: кадр 4,69 Мп (~457 КБ base64)
   уходил каждый шаг по новому TCP+TLS-соединению через VPN, и модель получала в ~3,5 раза
   больше vision-пикселей, чем нужно.

## Что изменено

### Доводка после краша на старте (2026-11-08, после отчёта роя)

Оборванный квотой Сборщик оставил четыре недовнедрённые правки — приложение падало при
запуске (`AttributeError: no attribute '_install_ui_snapshot_traces'`, окно закрывалось сразу):

| Фикс | Что было | Что стало |
|---|---|---|
| `_install_ui_snapshot_traces` | Вызов метода в `__init__` без самого метода — крах на старте | Метод дописан: зеркалит Tk-переменные (ключ/модель/подсказка/мышь/задержка) в `_ui_snapshot`; worker-поток читает словарь, а не Tk (безопасно между потоками) |
| `resolve_click_scale` | Функция определена, но не вызывалась — фикс координат не работал | Подключена в `execute_one_cycle` вместо старой эвристики «<=100 значит проценты» |
| Поколения воркеров | `_worker_generation`/`should_abort` инициализированы, логики не было | СТАРТ поднимает поколение; устаревший воркер не кликает (проверка после API-ответа) и не глушит новый режим; СТАРТ заблокирован во время одиночного шага |
| Fallback-скрытие окна | `_capture_hide_*` инициализированы, не использовались | Если WDA не сработал (старые Windows): окно прячется на время снимка из worker-потока (withdraw → захват → возврат), пояснение в журнал один раз |

### Поддержка заданий-сопоставлений («соедини колонки»)

Модель соединяла элементы в одной колонке — промпт ничего не знал про такие задания.
Добавлено (2026-11-08, вечером):

- **Правила сопоставления в промпте**: выбрал элемент в одной колонке → следующий клик в
  противоположную; никогда не соединять два элемента одной колонки; не соединять уже связанную пару.
- **Пометка колонки в истории**: каждая запись истории теперь говорит, слева или справа был
  клик (`[left column]` / `[right column]`) — модель видит, что только что выбрала выражение
  слева, и кликает ответ справа.
- **Действие `drag`** (`x1,y1 → x2,y2`): если интерфейс требует тянуть линию мышью, модель
  возвращает drag; исполнитель делает `moveTo → mouseDown → moveTo → mouseUp`, превью рисует
  линию между точками. Проверка самоклика работает для обеих точек.
- **`done` без координат** больше не считается ошибкой шага.

## Как проверить руками

1. Запусти `Запустить_AI_кликер.bat` (или `python screen_agent.py`).
2. В журнале при старте должно появиться сообщение об исключении окна из захвата (✅ или ⚠️ с причиной).
3. Выдели область с тестом, нажми СТАРТ. Ожидаемо:
   - окно программы не видно в превью-скриншотах и не мешает модели;
   - после каждого клика строка «📊 Экран после клика изменился/НЕ изменился (различающихся пикселей: N из M, порог 4)»;
   - если модель кликает в уже выбранную опцию, в промпт уходит история, и она жмёт «Далее»;
   - при реальном зависании — «🛑 Зависание… останавливаю авто-режим»;
   - в журнале видно «X.Xс API, 0.0Yс подготовка» — шаг должен стать заметно быстрее (было 5–8 с).

## Настройки-ручки (константы)

| Константа | Файл | Смысл |
|---|---|---|
| `MIN_CHANGED_PIXELS = 4` | `agent_progress.py` | Порог «экран изменился». Если прогресс пропускается — уменьшить; если ловит шум — увеличить |
| `SNAPSHOT_WIDTH = 256`, `PIXEL_DIFF_TOLERANCE = 25` | `agent_progress.py` | Размер снапшота сравнения и допуск на шум JPEG |
| `STAGNATION_REPEAT_LIMIT = 3`, `STAGNATION_NO_CHANGE_LIMIT = 3`, `SAME_TARGET_TOLERANCE_PX = 20` | `agent_progress.py` | Когда считать цикл зависшим |
| `max_side=1536`, `quality=80` | `agent_speed.py` | Размер кадра и качество JPEG для API |

## Предупреждения

- После `WDA_EXCLUDEFROMCAPTURE` окно программы пропадает и из **сторонних** скриншотов
  (Win+Shift+S, OBS, шаринг экрана) — это нормально и побочный эффект самой техники.
- При пересборке `Tools.exe` (pyinstaller) новые модули `agent_window.py`, `agent_progress.py`,
  `agent_speed.py` нужно включить в сборку (hiddenimports/data).
- pytest в системе не установлен — тесты гоняются через `python -m unittest`.

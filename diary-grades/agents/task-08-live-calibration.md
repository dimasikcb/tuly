## Как сейчас… Порядок (для дублей, если портал поменяет API/DOM)

1. Запустить приложение, войти через Госуслуги, нажать «Обновить оценки».
2. Если статус «не найдено оценок» — открыть «Папка debug»:
   `page.html`, `urls.txt`, `responses/NN.json`.
3. По `urls.txt` найти реальный endpoint с оценками → обеспечить присутствие его
   слов в `json_url_keywords` (сейчас помимо них идёт прямой запрос к API).
4. По `responses/NN.json` посмотреть реальные ключи предмета и оценок →
   убедиться, что `parse_marks_api` их покрывает (`subject_name`, `value`,
   `date`, `created_at`, `id`).
5. Если SPA сломает прямой API — уточнить `subject_row_selectors`,
   `mark_selectors`, `grades_nav_texts`, `period_nav_texts`.
6. Проверить выбор текущего периода: `config.current_period()` должен совпадать
   с тем, что выделено на портале (четверть/триместр). При несовпадении — поправить
   границы в `config.QUARTERS` / `TRIMESTERS` (это уже задача агента по `config.py`).
7. Добавить в `tests/test_parsers.py` **реальную обезличенную фикстуру** (без ФИО,
   без токенов, только предметы и оценки) и прогнать весь набор (не меньше 110).

## Что НЕ делать

- Не сохранять cookies/`storage_state`, ФИО, токены и персональные данные в репозиторий.
- Не выключать системный VPN/прокси и не менять сетевые настройки.
- Не хардкодить селекторы в `diary_client.py`/`app.py` — всё через `selectors.json`.
- Не выдавать демо-данные за реальные.
- Не вносить маркеры `user_agent` в код: портал привязывает сессию к браузерному
  отпечатку — с кастомным UA скрытый контекст получает `403` на `/marks`.

## Критерий готовности

- `Обновить оценки` в headless-режиме возвращает предметы и оценки из живого дневника,
  период совпадает с текущим, `debug/` не пополняется дампами ошибок;
  145 тестов зелёные; кэш `live` с 18 предметами (16 с оценками), `source` ≠ demo/import.

`/marks` отдаёт только предметы, по которым уже есть оценки. Полный список —

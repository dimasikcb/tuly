# Дневник МО · Контроль балла

Оконное приложение на Python: забирает оценки из электронного дневника Московской области
(`https://authedu.mosreg.ru`), считает, сколько пятёрок нужно для среднего 4.50
и какой «запас прочности» есть у пятёрочника. Тёмный UI, один клик, без терминала.
Платформы: **Windows 11** и **Fedora Linux**.

> Честно: селекторы портала не проверены против живой сессии (доступа к дневнику нет).
> Парсер адаптивный — сначала читает JSON-ответы SPA, потом DOM, а при неудаче
> сохраняет диагностику в `debug/`. Есть импорт сохранённой страницы и правка
> `selectors.json` без изменения кода. Подробности — раздел «Калибровка».

## 0. Вкладка в хабе «Мои инструменты» (Windows)

Приложение уже встроено в общий хаб `../tools.pyw` / `../Tools.exe`: пункт
**«Дневник МО»** стоит в левом сайдбаре между «Лиды 2GIS» и «Shorts Autopilot»
(`Ctrl+8`). Вкладка показывает ту же таблицу, что и отдельное окно, читает тот же
кэш `data/grades_cache.json` и обновляется сама, когда окно приложения записало
новые оценки. Кнопки «Обновить оценки», «Войти заново», «Окно», «Демо»,
«Импорт», «Папка» работают через отдельный процесс `.venv/Scripts/python.exe`
(у хаба может не быть Playwright). Переключаться между вкладкой и окном можно
в любой момент. Сборка в EXE отключена — хаб запускается напрямую через `python ../tools.pyw`.

### Реальные оценки без входа через Госуслуги

В демо-наборе предметы выдуманы: `Обществознание` там `3.33` (`3,3,4,…`),
а в реальном дневнике — `4.00` (`4,4,4`). Как только появляется кэш, демо
не показывается: плашка меняется с **ДЕМО-ДАННЫЕ** на **КЭШ**.

Быстрый путь без ЕСИА — файл **`real_grades.json`** в корне подпроекта:

```json
{
  "period": "1 триместр 01 сент – 15 ноя",
  "subjects": [
    {"name": "Обществознание", "marks": [4, 4, 4]},
    {"name": "Математика", "marks": []}
  ]
}
```

Впиши оценки 1..5 в `marks` у нужных предметов, сохрани и нажми **«Импорт»**
в окне или на вкладке хаба. Предметы с пустым `marks` не выдумываются и не
выбрасываются: они попадают в таблицу строками «нет оценок · нужен вход»,
уходят в конец сортировки, а плашка показывает **КЭШ · ЧАСТИЧНО** и счётчик
«12 · с оценками 1». Файл пишется в `data/grades_cache.json`, обе программы
подхватывают его автоматически.
По умолчанию стоит схема **триместров** (`1 триместр 01 сент – 15 ноя` — как в
реальном дневнике); границы лежат в `config.py::TRIMESTERS`, для четвертей
выстави `period_scheme: "quarters"` в `data/settings.json` или в «Настройках».

### Обновление по всем предметам сразу

Для всех предметов нужен один вход через Госуслуги: **«Войти заново»**, затем
**«Обновить оценки»** (без сессии кнопка сама открывает вход ЕСИА). После этого
сборщик берёт не только первый предмет со страницы:

- список ожидаемых предметов читается из `real_grades.json`
  (`config.expected_subjects()`, сейчас 16 реальных предметов);
- каждый предмет, у которого ещё нет оценок, открывается отдельно, ответы API и
  DOM складываются без дублирования (`diary_client._merge_best`);
- недостающие предметы дописываются пустыми строками, поэтому в кэш и таблицу
  всегда попадают **все предметы из шаблона**, а статус показывает
  «предметов — N, с оценками — M».
- **Прямой запрос к `/api/family/web/v1/marks`** забирает весь период одной
  сетевой операцией — никаких обходов по страницам.

Вкладка хаба дополнительно раз в `auto_refresh_min` (по умолчанию 30 минут,
`0` — выключить) тихо обновляет все предметы, **но только если сессия уже
сохранена**: скрытое автообновление никогда не открывает браузер для логина.
Окно приложения тоже обновляется само: сразу после входа, если в кэше остались
пустые предметы, и дальше по таймеру. Таймаут обхода предметов —
`subject_scan_timeout_s`. Селекторы под живой портал калибруются по дампу из
`debug/` (см. «Калибровку» ниже).

## 1. Запуск в один клик

| | Что сделать один раз | Как запускать потом |
|---|---|---|
| **Windows 11** | Установить Python 3.10+ **с tcl/tk** и галочкой «Add python.exe to PATH» | Двойной клик по `run.bat` |

> Windows: `run.bat` берёт `py -3` (системный Python). Если в PATH первым стоит
> встроенный в IDE Python без `tkinter`, GUI не поднимется. Проверка:
> `py -3 -c "import tkinter; print(tkinter.TkVersion)"`.
| **Fedora** | `sudo dnf install python3 python3-pip python3-tkinter python3-devel libX11-devel gtk3` | Ярлык «Дневник МО» в меню приложений |

`run.bat` / `run.sh` при первом запуске сами создают `.venv`, ставят зависимости из
`requirements.txt` и скачивают Chromium для Playwright. Это единственный раз, когда
видно окно установки. Все последующие запуски — сразу окно программы, без консоли
(Windows: `pythonw.exe`; Linux: `Terminal=false` в `.desktop`).

Fedora — установка ярлыка **симлинком** (важно: `%k` в `Exec` должен указывать на исходный файл в папке проекта):

```bash
cd diary-grades
chmod +x run.sh diary.desktop
ln -s "$PWD/diary.desktop" ~/.local/share/applications/diary.desktop
```

Если Chromium ругается на системные библиотеки:
`sudo .venv/bin/python -m playwright install-deps chromium`.

Разовая установка вручную (не обязательна, лаунчеры делают это сами) — команды
в начале `requirements.txt`.

## 2. Первый и последующий запуски

1. Окно открывается сразу: кнопка **«Обновить оценки»**, статус **«Загрузка…»**.
   Если кэша нет — таблица с демо-данными и жёлтая плашка **ДЕМО-ДАННЫЕ**
   (выдуманные числа, это не реальные оценки). Если кэш есть — плашка **КЭШ**.
2. Нет `data/storage_state.json` → через секунду открывается **видимое окно Chromium**.
   Войди вручную через Госуслуги (ЕСИА). Пароль приложение не видит и не хранит.
   После успешного входа cookies/`storage_state` сохраняются в `data/`, браузер закрывается,
   сразу запускается сбор оценок.
3. Дальше **«Обновить оценки»** работает **скрытно (headless)**, браузер закрывается сам.
4. Сессия протухла → статус «Сессия истекла», кнопка **«Войти заново»**.
5. Нет сети/доступа? **«Импорт HTML/JSON»** — сохрани страницу оценок из браузера
   (или JSON-ответ) и загрузи файл. **«Демо-данные»** — проверить интерфейс.

Кнопки: `Обновить оценки` · `Войти заново` · `Импорт HTML/JSON` · `Демо-данные` ·
`Настройки` (четверти/триместры, headless) · `?` (справка) · `Папка debug`.

## 3. Что показывает таблица

Сортировка **строго от худшего среднего к лучшему** (точное сравнение через `Fraction`,
не float). Поиск по названию предмета — живой фильтр над таблицей.

| Столбец | Содержание |
|---|---|
| Предмет | Название |
| Средний балл | `S/N`, бейдж: 🔴 < 3.50 · 🟡 3.50–4.49 · 🟢 ≥ 4.50 |
| Текущие оценки | Все оценки за период (полный список — внизу по клику) |
| До 5-ки | Сколько пятёрок подряд нужно; для пятёрочника — «✓ на 5» |
| Запас прочности | `4→2 · 3→0 · 2→0` — сколько четвёрок/троек/двоек подряд выдержит балл |

Клик по строке — разбор формулы с конкретными числами.

**Математика** (простое среднее, порог 4.50 = 9/2, всё целочисленно, без ошибок округления):

- `S` — сумма, `N` — количество, `2·S ≥ 9·N` ⟺ на пятёрке.
- Если ниже: `k = ceil((4.5·N − S) / 0.5) = 9·N − 2·S` пятёрок подряд.
- Если на пятёрке: запас `D = 2·S − 9·N`; для оценки `v ∈ {2,3,4}` безопасно
  `floor(D / (9 − 2·v))` таких оценок подряд, на следующей балл впервые станет **< 4.50**.
  Ровно 4.50 падением не считается. Пятёрки не роняют балл никогда.

Пример: `S=46, N=10` (4.60) → две четвёрки подряд держат ровно 4.50, третья роняет;
первая же тройка даёт 4.45.

## 4. Калибровка под живой портал

Сайт — SPA с авторизацией через ЕСИА. Сейчас данные идут **прямо из API**:
`/api/family/web/v1/profile` (получить `student_id`) и
`/api/family/web/v1/marks?student_id=...&from=...&to=...` за весь период —
запрос без браузера, с заголовками `authorization: Bearer <aupd_token>`,
`profile-id`, `profile-type: student`, `x-mes-roleid`, `x-mes-subsystem`.
Отклик — плоский список записей, одна строка = одна оценка (`subject_name`,
`value`, `date`, `created_at`).

Остались уровни пониже (обход страницы и DOM):

1. **Перехват JSON-ответов** (`page.on("response")`) — URL с `mark/grade/diary/journal/...`,
   рекурсивный разбор `parsers.parse_grades_payload`.
2. **DOM** — `parsers.parse_grades_html`: таблицы строк «предмет + ячейки оценок»
   и div-карточки с `data-subject` / `data-mark`. Средний балл `4,50` и даты в оценки не считаются.
3. **Диагностика** — если ничего не найдено, в `debug/` пишутся `page.html`, `urls.txt`
   и `responses/NN.json`. По ним правится `selectors.json` (ключи `json_subject_keys`,
   `json_marks_keys`, `grades_nav_texts`, `subject_row_selectors`, …) — код трогать не нужно.

Навигация по разделу оценок и выбор текущего периода (`1..4 четверть` / `1..3 триместр`)
делаются «мягко»: по текстам из `selectors.json` и `config.current_period()`.
Схема периодов переключается в «Настройках».

Данные только локальные: `data/grades_cache.json` (кэш), `data/storage_state.json`
(сессия, POSIX-права 0600), `debug/` (дампы). Никуда не отправляются.

## 5. Структура и тесты

```
app.py           GUI: CustomTkinter, таблица на фреймах (бейдж в ячейке), потоки, кэш, автообновление
app.pyw          вход без консоли для Windows + лог ошибок запуска
grade_math.py    математика: k, запас прочности, бейджи, сортировка (чистые функции)
models.py        dataclass'ы: SubjectGrades / SubjectReport / FetchResult / Period
config.py        пути, настройки, текущий учебный период, атомарная запись JSON, expected subjects
parsers.py       JSON-ответы + HTML → предметы (только stdlib), парсер прямого API /marks
diary_client.py  Playwright: ручной вход ЕСИА, headless-сбор, прямой API-запрос за весь период
real_grades.json шаблон/источник 16 реальных предметов портала (текущий 1 триместр)
demo_data.py     демо-набор (12 предметов)
selectors.json   эвристики вёрстки/API — правится без правки кода
run.bat / run.sh / diary.desktop / requirements.txt
agents/          самодостаточные задания для ИИ-агентов (старт: 00-INDEX.md)
tests/           110 офлайн-теста: математика (перебор всех S,N), парсер API, клиент, сборка, автообновление
```

```bash
python -X utf8 -m unittest discover -s tests -v
python app.py --demo                      # окно без браузера
python app.py --smoke-shot debug/gui.png  # автопрогон GUI + скриншот + debug/smoke_report.json
```

Тесты не ходят в сеть и не запускают браузер (Playwright подменяется моками).

## 6. Известные ограничения

- **Проверено на живом портале с реальной сессией:** `/api/family/web/v1/profile`,
  `/api/family/web/v1/marks` за весь период — 18 предметов класса, 16 с оценками,
  124 числовые оценки (кеш `data/grades_cache.json` — `live`, `1 триместр`).
  Полный список предметов берётся из `profile` → `children[].groups[].name`:
  ответ `/marks` содержит только предметы с оценками, поэтому «Вероятность и
  статистика» и «Математика» иначе молча пропадают из таблицы. Они остаются
  строками «нет оценок в периоде» в конце.
- **Автообновление:** в окне приложения и во вкладке хаба — сразу после входа,
  если в кэше есть предметы, по которым ожидались оценки, и потом по таймеру
  `auto_refresh_min` (в «Настройках», 0 = выключить). Предметы, пустые в самом
  шаблоне `real_grades.json`, «дырами» не считаются и браузер не дёргают.
  Без сохранённой сессии браузер не открывается автоматически.
- ЕСИА может требовать MFA/СМС — вход всегда ручной, автоматический обход не делается.
- Оценки предполагаются целыми 1..5; дробные/весовые отклоняются с явной ошибкой.
- При первом запуске на Windows консоль установки видна один раз — дальше `pythonw.exe`.
